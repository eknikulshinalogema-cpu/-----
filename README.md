# Дашборд аналитики сделок CRM для Битрикс24 (VibeCode)

Встраиваемое приложение (левое меню Битрикс24), показывающее каждому
сотруднику аналитику по его собственным сделкам CRM: сводку по стадиям
воронки, ключевые показатели и последние сделки.

## Функции

- **Сводка по стадиям воронки** — количество и сумма сделок по каждой стадии.
- **Ключевые показатели** — сумма открытых сделок, число выигранных за период,
  средний чек по выигранным сделкам.
- **Последние сделки** — список из 10–20 сделок (название, сумма, стадия,
  ответственный).
- **Фильтр по периоду создания** — весь период (по умолчанию), сегодня,
  вчера, неделя, месяц, квартал, год, произвольный диапазон.
- **Фильтр по воронке** — конкретная воронка или "Все воронки" (по умолчанию).
- Явные пустые состояния ("Нет данных"), индикаторы загрузки, автообновление
  при смене фильтров.

## Архитектура (BFF)

```
Битрикс24 (iframe) → Gateway VibeCode → наш бэкенд (Express) → VibeCode API
                                              │
                                              └─→ статика фронтенда
```

Фронтенд **не обращается к VibeCode API напрямую** — только к своему
бэкенду (`/api/dashboard/*`). Все вызовы к VibeCode API идут с сервера,
с READONLY API-ключом в заголовке `X-Api-Key`. Ключ хранится только в
`.env` и никогда не попадает в код, логи или ответы фронтенду.

### Определение текущего пользователя

- Gateway VibeCode прикладывает к запросам, приходящим из встроенного
  приложения, заголовки `X-Vibe-User-Id` / `X-Vibe-User-Name` (и, возможно,
  `X-Vibe-User-Email`) — бэкенд читает их **из входящего запроса** и
  фильтрует сделки по `ASSIGNED_BY_ID = X-Vibe-User-Id`.
- `GET /v1/me` дополнительно используется при старте сервера для проверки,
  что ключ валиден и платформа доступна.
- **Важно (требует проверки на боевом стенде):** точные названия заголовков
  Gateway и способ кодирования в них кириллицы (percent-encoding vs UTF-8)
  не были подтверждены документацией на момент разработки (страница
  `https://vibecode.bitrix24.tech/v1/me` отдавала 401 без интерактивной
  сессии). Места, требующие сверки, помечены в коде комментарием
  `ПРОВЕРИТЬ:` — в первую очередь `backend/config.js` (`gatewayHeaders`) и
  `backend/middleware/auth.js`.

## Используемые скоупы и ограничения

- Скоупы: **`crm`**, **`user`**.
- Режим ключа: **READONLY**.
- Запись/изменение данных в CRM приложение не выполняет — только чтение.
- Персональные данные (название сделок, суммы, e-mail и т.п.) не логируются
  (см. `backend/utils/logger.js` — фильтр запрещённых ключей).

## Структура проекта

```
backend/
  config.js              — загрузка конфигурации из .env
  server.js               — точка входа Express
  routes/dashboard.js     — эндпоинты /api/dashboard/*
  services/vibeApi.js     — HTTP-клиент VibeCode API (retry/backoff, batch)
  services/crm.js         — бизнес-логика: воронки, стадии, сделки, метрики
  middleware/auth.js      — определение текущего пользователя (Gateway headers)
  utils/validation.js     — валидация входных параметров
  utils/dateRange.js      — вычисление диапазона дат по period
  utils/cache.js          — кэш справочников (TTL 5 минут)
  utils/logger.js         — логирование без чувствительных данных
  .env.example            — шаблон переменных окружения (без секретов)
frontend/
  index.html               — разметка дашборда
  css/style.css            — стили в цветовой схеме Битрикс24
  js/app.js                — логика фильтров и рендеринга (без ключей)
```

## Эндпоинты бэкенда

| Метод | Путь | Параметры | Описание |
|---|---|---|---|
| GET | `/api/dashboard/funnels` | — | список воронок для фильтра |
| GET | `/api/dashboard/stages` | `period, from, to, funnel` | сводка по стадиям |
| GET | `/api/dashboard/metrics` | `period, from, to, funnel` | ключевые показатели |
| GET | `/api/dashboard/recent` | `period, from, to, funnel, limit` | последние сделки |
| GET | `/api/health` | — | проверка живости сервиса |

Параметр `period`: `all` (по умолчанию) \| `today` \| `yesterday` \| `week` \|
`month` \| `quarter` \| `year` \| `custom` (требует `from`/`to` в формате
`YYYY-MM-DD`). Параметр `funnel`: ID воронки (число) или `all`.

## Обработка ошибок

| Код | Сообщение пользователю |
|---|---|
| 401 | Сессия истекла, обновите страницу |
| 403 | Недостаточно прав для просмотра данных |
| 429 | Слишком много запросов, подождите... (с автоматическим retry на бэкенде, экспоненциальная задержка) |
| 502 | Сервис временно недоступен |
| прочие | Общее сообщение пользователю, подробности — в серверном логе |

## Как проверить

1. Установить зависимости и запустить:
   ```bash
   cd backend
   npm install
   npm start
   ```
2. Открыть `http://localhost:3000/` — интерфейс должен загрузиться, карточки
   покажут индикаторы загрузки, затем данные (или "Нет данных").
3. `GET /api/health` должен вернуть `{"status":"ok"}`.
4. Проверить, что в исходниках фронтенда (`frontend/js/app.js`,
   `frontend/index.html`) и в ответах `/api/dashboard/*` нигде не встречается
   значение `VIBE_API_KEY`.
5. Проверить смену фильтров периода/воронки — данные должны обновляться
   автоматически без перезагрузки страницы.
6. Локально проверено на mock-сервере, эмулирующем VibeCode API: retry при
   429 (экспоненциальный backoff), корректная агрегация по стадиям,
   расчёт метрик (сумма открытых, число выигранных, средний чек),
   пустая сводка при выборе воронки без сделок, отклонение некорректных
   query-параметров (400) и требование заголовков Gateway в production
   (401 при их отсутствии).
7. Перед боевым запуском внутри Битрикс24 нужно сверить с реальной
   документацией VibeCode три места, помеченные `ПРОВЕРИТЬ:` в коде
   (см. раздел "Определение текущего пользователя" выше и комментарии в
   `services/crm.js`, `services/vibeApi.js`) — контракт `crm.status.list`
   (поле семантики WON/LOSE), контракт `POST /v1/batch` и названия
   заголовков Gateway.

## Переменные окружения (`.env`)

```
VIBE_API_KEY=<ваш READONLY-ключ>
PORT=3000
NODE_ENV=production
```

`.env` добавлен в `.gitignore` и не должен попадать в систему контроля версий.
